- [ ] 定义 Agent/会话/threadId、状态机、计划版本、可序列化状态、稳定 effect_key 和消息写入归属；不延后到阶段 3。

## 阶段 3：中断、恢复与取消

- [ ] 在阶段 1 已验证持久化的基础上，扩展完整图 checkpoint 及状态恢复；核对所有节点可序列化状态和结果引用。
- [ ] 人工审核 interrupt、接受恢复、拒绝重新规划；保留原参数契约。
- [ ] 待审核时重启服务并刷新页面，重新进入会话，调用 active-run 重建 lastRequest、计划及审核按钮，再通过同一 threadId 恢复。
- [ ] 同一会话串行创建/恢复：待审核时新问题被拒绝，重复反馈和旧 planRevision 不会触发第二次恢复。
- [ ] 覆盖 Redis 释放/续期 token 比较、锁过期、Redis 不可用、恢复前后崩溃与 checkpoint/运行记录不一致；旧任务未确认停止不放行新任务。
- [ ] 验证消息保存重试不重复；拒绝后原计划被替换，成功计划仅提交一轮模型记忆。
- [ ] 在线拒绝并再次审核时，事件里的 plan/planRevision 与卡片绑定；旧卡片不能读取新版号后批准新计划。
- [ ] 实现本机恢复 CLI，覆盖证据不足拒绝、确认停止后失败收尾、过期 version 拒绝、重复操作幂等及会话重新可用。
- [ ] 覆盖完成后浏览器保存前断开、终态提交后 SSE 发送前崩溃；重进会话找回同一最终结果，补存不重复。
- [ ] 审核中修改数据源/选表/模型/提示词使旧计划失效；当前权限不能被快照绕过，纯展示变更和凭据轮换按例外处理。
- [ ] 按 threadId 或 conversationId 停止，断连取消；核对 204 响应。
- [ ] 模型流、数据库操作、文件与连接的超时和资源释放。
- [ ] 成功、失败、取消和待审核历史状态及终止事件行为。

验收：后端重启＋页面刷新后接受与拒绝各完成一次；双标签页新问题、待审核期间新问题、双击反馈及旧版本反馈均符合会话占用规则。锁过期不产生第二个执行；跨存储故障能对账，或进入 RECOVERY_REQUIRED 后由 CLI 在确认停止后完成失败收尾并让会话重新可用。证据不足继续保留占用。最终结果能跨前端保存失败找回，配置变化不静默执行旧计划；停止、断连、异常无错误释放占用或重复终止事件。取消数据库操作的实际效果单独记录。

## 每次实现迭代的收尾

1. 更新接口或阶段任务状态，记录实际验证结果与剩余差异。
2. 进行与本次变更相关的必要检查；文档变更检查链接及内容即可。
3. 查看适用的 `.gitignore`，按新增产物决定是否更新；未来关注 `.venv`、缓存、密钥、日志、上传文件、向量索引和 checkpoint 本地文件。
4. 仅暂存本次任务文件，保留已有工作区改动，提交带有明确描述的 Git commit。
